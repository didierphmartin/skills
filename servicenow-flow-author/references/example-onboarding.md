# Reference example — new employee onboarding (EN + FR)

The procedure a user pastes, the spec you write, and the flow `create.py` generates (vendor `1234567`). Generated by `dev/build_example.py`; the build gate compiles both flows with `now-sdk build` (0 errors).

## The procedure (English)

> New employee onboarding
>
> When HR creates a new user record for an employee who hasn't started yet, start the onboarding.
>
> First ask the new hire's manager to approve the onboarding and confirm the equipment list. If the manager rejects it, notify HR with the reason and stop there.
>
> Once approved, in parallel:
> - create a task for the IT service desk to set up the accounts (email, VPN, the department's apps);
> - create a task for Facilities to prepare the desk and the badge.
>
> For each item on the approved equipment list (laptop, monitor, phone…), create a separate hardware request task for the IT hardware team.
>
> Send the new hire's manager an email summarising what was requested and the start date.
>
> Two working days before the start date, check that all the tasks are closed. If some are still open, remind the assignment groups; if they're still open on the start date, escalate to the IT manager and inform HR.
>
> On the start date, send the new hire a welcome email with their first-day information, and log that onboarding is complete.

## The procedure (French)

> Intégration d'un nouvel employé
>
> Lorsque les RH créent la fiche utilisateur d'un nouvel employé qui n'a pas encore commencé, lancer l'intégration.
>
> Demander d'abord au responsable de la nouvelle recrue d'approuver l'intégration et de confirmer la liste d'équipement. Si le responsable refuse, prévenir les RH en indiquant le motif et s'arrêter là.
>
> Une fois l'intégration approuvée, en parallèle :
> - créer une tâche pour le centre de services informatiques afin de configurer les comptes (messagerie, VPN, applications du service) ;
> - créer une tâche pour les Services généraux afin de préparer le bureau et le badge.
>
> Pour chaque article de la liste d'équipement approuvée (ordinateur portable, écran, téléphone…), créer une tâche distincte de demande de matériel pour l'équipe matériel informatique.
>
> Envoyer au responsable de la nouvelle recrue un courriel récapitulant ce qui a été demandé et la date de début.
>
> Deux jours ouvrés avant la date de début, vérifier que toutes les tâches sont fermées. Si certaines sont encore ouvertes, relancer les groupes d'affectation ; si elles sont encore ouvertes à la date de début, escalader au responsable informatique et informer les RH.
>
> À la date de début, envoyer à la nouvelle recrue un courriel de bienvenue avec ses informations pour le premier jour, et journaliser que l'intégration est terminée.

## How each sentence maps

| Procedure | Spec |
|---|---|
| When HR creates a new user record for an employee who hasn't started yet, start the onboarding | trigger `service_catalog`: HR orders the onboarding catalog item right after creating the user; the sentence becomes `form.submitted_by` (the catalog item's description and "Who submits this form and when" in FLOWS.md) |
| (the data the steps need) | `form.variables`: new hire, manager, department (reference), start date (date), equipment (list_collector on `cmdb_model`), first-day information (multi_line_text) |
| ask the new hire's manager to approve the onboarding and confirm the equipment list | `askForApproval` on the requested item (`trigger.request_item`, `sc_req_item`), approver `form.manager`: the manager approves the request that carries the equipment list |
| If the manager rejects it, notify HR with the reason and stop there | `if` approval_state != approved (any outcome other than approved takes the stop path) → `sendNotification` (placeholder; the notification shows the approval comments) + `end` |
| in parallel: a task for the IT service desk … a task for Facilities | `parallel` with two `createCatalogTask` on the request item, `ah_wait: false`, group placeholders |
| For each item on the approved equipment list … a separate hardware request task | a list collector answer is a comma-separated string of sys_ids, not an array (`forEach` iterates arrays only: wfa-flow-logic-api.md:134-135), so `lookUpRecords` on `cmdb_model` with `sys_idIN` + the answer → `for_each` over `Records` → one `createCatalogTask` per item |
| Send the new hire's manager an email summarising what was requested and the start date | `sendEmail` to `form.manager.email`; the new hire and the start date go in the subject (an email body takes no pills: action-api.md:256), the body lists what was requested |
| Two working days before the start date, check … remind the assignment groups | `wait_duration` 2 days `before` `form.start_date` with a `working_days_schedule` placeholder → `lookUpRecords` open `sc_task` of the request item → `if` Count > 0 → `for_each` → `sendNotification` |
| if they're still open on the start date, escalate to the IT manager and inform HR | `wait_duration` 9 hours `after` `form.start_date` → `lookUpRecords` → `if` → two `sendNotification` |
| welcome email with their first-day information, and log | `sendNotification` (placeholder on the request item, which can show the First-day information variable; a `sendEmail` body cannot carry it), then `log` |

The French spec is the same flow: same ids, variables and structure, every `label`, question, subject, body and message in French, and its own `name` (`integration-nouvel-employe`).
